# Entrega de implementación local

Rama `migration/react-editorial-security`, base `0f6ab9b`. Sin push, despliegue público, rotación de credenciales ni cambios de datos/políticas remotos.

1. **Conservado:** Supabase/PostgreSQL, tablas y bucket identificados, campos de libros/artículos/destacados, HTML antiguo sin editar, rutas públicas `.html`, Google/correo/registro, contacto real, biografía, fotografía original, promoción y enlaces de Junior Osmany. Los registros desconocidos del catálogo no se eliminan ni se filtran por autor.
2. **Migrado:** frontend React/TypeScript estricto con Vite y Router; consultas/caché TanStack; Supabase v2 por entorno; formularios RHF/Zod; panel con CRUD, búsqueda/filtros, borradores, orden transaccional, vistas previas y editor enriquecido; gestión de miembros mediante SQL de servidor; upload mediante Edge. La lectura pública real fue comprobada; las nuevas operaciones administrativas requieren un backend de staging compatible. La columna opcional `libros.visible` queda fuera de las migraciones básicas y la aplicación admite su ausencia, confirmada en la API original.
3. **Apariencia original recuperada:** CSS original, roble/dorado, Cinzel/Montserrat, fondos, fotografías, cabecera, textos, catálogo detallado, tarjetas, contacto, login modal y panel con pestañas horizontales. Se sustituyó la reinterpretación editorial anterior después de comparar ambas versiones. Se revisaron 24 pares de capturas en escritorio, tableta y móvil antes y después de la corrección; la etapa final utiliza los registros públicos reales. Evidencia y diferencias justificadas en `VISUAL_FIDELITY.md` y `.qa/visual/report.html`.
4. **Seguridad:** retiradas interpolaciones HTML peligrosas del nuevo runtime, sanitización, URLs y payloads validados, autorización denegada por defecto, migración RLS restrictiva, roles privados, protección del último administrador activo, cuotas y validación de imágenes en servidor. Pruebas locales dan evidencia del código y del SQL propuestos; no certifican seguridad de producción.
5. **Supabase pendiente de autorización:** se leyeron por API pública dos libros, dos artículos publicados y dos destacados activos; también se ejecutaron las consultas reales de los servicios React con éxito, sin escrituras remotas. Falta inspeccionar tipos/esquema completo y configuración, crear staging/respaldo, aplicar las migraciones de seguridad y orden revisadas, inicializar UUIDs legítimos, desplegar Edge y configurar origins/OAuth. No aplicar estas políticas mientras el panel antiguo siga en uso. Revisar tablas expuestas adicionales y políticas restrictivas preexistentes.
6. **Pruebas:** 43 unitarias/SQL y 30 casos funcionales en tres resoluciones aprobados, más siete anchuras verificadas del hero definitivo. Se conservan las comparaciones visuales de las etapas anteriores como evidencia histórica. Compilación de cliente/SSR y escaneo de claves correctos. Resultados y límites en `TESTING.md`. El ensayo contra staging se detuvo por falta de configuración; no fue simulado como exitoso. El control de tipos Deno revisa la función Edge, sin desplegarla.
7. **Antes del despliegue:** completar matriz real de staging, revisar diferencias de esquema/HTML/enlaces, ensayar rollback, comprobar Vercel SSR/CSP/redirects, obtener respaldo reciente y autorización de corte. Las URLs de APK públicas y el bucket de imágenes público no se convierten en repositorios privados por incorporar login.

La eliminación de una publicación no borra físicamente sus imágenes, para proteger referencias compartidas. La limpieza de objetos requiere inventario y revisión de Storage; no existía borrado automático en el código original. Esto no impide cambiar portadas desde el panel.
